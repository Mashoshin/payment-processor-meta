# Черновик плана из идеи

Вход: идея в свободной форме (текст пользователя). Если идеи нет — спроси.

## Когда план нужен, а когда нет

План обязателен, если изменение затрагивает больше одного сервиса, меняет
контракты или инварианты из `map.md`. Для мелочи внутри одного сервиса
предложи сразу завести тикет и остановись.

## Шаги

1. Прочитай `map.md`, манифесты `registry/` и релевантные контракты.
2. Создай `plans/P-NNN-<slug>.md` из `plans/PLAN.template.md`
   (NNN — следующий свободный номер).
3. Секция «Идея (дословно)» — текст пользователя без изменений.
4. Заполни «Цель», «Контекст» (со ссылками на конкретные места в документах
   меты, включая раздел «осознанные дыры»), «Варианты решения» (минимум два,
   честные плюсы/минусы), «Выбранный вариант и почему», «Риски».
5. В «Открытые вопросы» вынеси все решения, которые может принять только
   человек (продуктовые развилки, компромиссы). Не принимай их сам —
   максимум рекомендация с аргументом.
6. status: draft.

## Ограничения

- Не выходи за идею: план — про одну связную вещь, а не «заодно ещё».
  Смежные идеи — списком в конце журнала, как кандидаты в отдельные планы.
- Контракты, код, тикеты — не трогать. Только файл плана.

## Выход

Файл плана + резюме: выбранный вариант, главные риски, открытые вопросы.
Следующий шаг — ответы человека на открытые вопросы и `/grill-plan`.
