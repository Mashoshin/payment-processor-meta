# Гриль-сессия

Вход: идея в свободной форме — аргументом после /grill. Нет идеи — спроси.

Формат: **диалог, а не файлы.** Вся работа идёт в контексте сессии;
ни один файл репозитория не создаётся и не правится — материализация
итогов — работа `/to-plan`. Ответы пользователя автоматически попадают
в журнал `sessions/` (хук), поэтому картина решений будет полной.

## Ход сессии

1. Прочитай `map.md`, манифесты `registry/` и релевантные контракты —
   вопросы должны опираться на реальное состояние системы.
2. Сформулируй для себя 2–3 варианта реализации идеи — они понадобятся
   для вопросов об альтернативах.
3. Задавай вопросы **пачками по 2–4**, жди ответов. Порядок:
   - сначала продуктовые развилки — решения, которые может принять
     только человек (например: «комиссия сверху или изнутри?»,
     «куда зачислять?»);
   - затем линии атаки: инварианты из `map.md` (деньги — целые копейки:
     округления!), границы сервисов и поведение при частичном сбое,
     вариант проще на 80 % ценности, лишний скоуп, краевые значения денег
     (минимальные суммы, нули, отрицательные).
4. **Спорь.** Если ответ противоречит инварианту или создаёт риск —
   возрази конкретным сценарием («перевод 55 копеек: комиссия 0,55 коп.,
   а суммы целые — как округляем?»). Но решение всегда за человеком:
   получил ответ после возражения — фиксируй и иди дальше.
5. Не затягивай: 2–3 раунда вопросов достаточно. Не выдумывай возражения
   ради возражений — нет реального сценария, значит вопроса нет.

## Финал сессии

Сводка «что решили» одним сообщением:
- идея (дословно, как её принёс пользователь);
- цель;
- выбранный вариант и отвергнутые альтернативы с причинами;
- все развилки и принятые решения;
- осознанно принятые риски.

Спроси подтверждение сводки. После подтверждения предложи `/to-plan` —
он превратит итоги в файл плана.
