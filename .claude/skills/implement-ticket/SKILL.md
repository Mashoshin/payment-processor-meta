# Реализация тикета

Вход: путь к тикету в `tickets/in-progress/`. Тикет в `open/` — остановись:
сначала декомпозиция и утверждение человеком.

## Шаги

1. Прочитай тикет. Проверь, что секции «Затронутые сервисы», «Изменения
   контрактов» и «Подзадачи» заполнены. Нет — остановись, отправь на
   `/decompose-ticket`.
2. **Сначала контракты.** Примени описанные в тикете правки к файлам
   в `contracts/`. Контракт правится до кода — всегда.
3. Убедись, что `workspace/` актуален (`scripts/bootstrap.sh`).
4. Для каждого затронутого сервиса создай worktree с веткой тикета:
   ```bash
   git -C workspace/<service> worktree add ../<service>-<ticket-id> -b <ticket-id>
   ```
5. **Запусти субагентов параллельно** — по одному на затронутый сервис,
   все в одном сообщении. Промпт каждого агента собирается из:
   - подзадачи этого сервиса из тикета (дословно);
   - контракта сервиса (`contracts/<service>.openapi.yaml`) целиком;
   - манифеста (`registry/<service>.md`);
   - рабочей директории: `workspace/<service>-<ticket-id>`;
   - правил: работать ТОЛЬКО в своей директории, чужие сервисы — только
     через их API, `var/` чужих сервисов не трогать, контракты не менять,
     в конце — закоммитить изменения в ветку тикета.
6. Дождись всех агентов. Итоги каждого запиши в «Журнал» тикета —
   включая то, что не получилось.

## Ограничения

- Сам код сервисов не пиши — это делают субагенты. Твоя роль — оркестрация.
- Merge в main сервисов НЕ делать: сначала `/cross-review`
  и `/integration-check`.

## Выход

Ветки `<ticket-id>` с коммитами в worktrees затронутых сервисов, обновлённые
контракты, заполненный журнал тикета. Резюме пользователю: что сделано по
каждому сервису, что дальше (cross-review).
