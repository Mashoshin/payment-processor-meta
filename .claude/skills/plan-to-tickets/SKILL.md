# План → тикеты

Вход: путь к плану в `plans/`.

## Предусловия (при нарушении — остановись и скажи почему)

- status: approved. Draft/grilled — сначала гриль и утверждение.
  Converted — уже сконвертирован, тикеты перечислены в шапке плана.
- «Открытые вопросы» пусты. Непустые — значит, решения не приняты,
  тикеты писать рано.

## Шаги

1. Прочитай план целиком, включая возражения гриля и ответы — в них часто
   зафиксированы решения, уточняющие выбранный вариант.
2. Разрежь план на тикеты. Правила нарезки:
   - один тикет = одна связная поставляемая вещь, проверяемая сквозным
     сценарием; не «тикет на сервис» — раскладкой по сервисам займётся
     `/decompose-ticket`;
   - тикеты упорядочены: если Б не имеет смысла без А — это зависимость,
     укажи её в тикете Б;
   - чаще всего из плана выходит 1–2 тикета. Больше трёх — вероятно,
     план был про несколько вещей сразу, скажи об этом.
3. Каждый тикет создай из `tickets/TICKET.template.md` в `tickets/open/`
   с именем `T-NNN-<slug>.md` (сквозная нумерация). Заполни:
   - «Задача» — бизнес-формулировкой из плана, своими словами, без
     технической разбивки;
   - «Критерий приёмки» — черновик сквозного сценария из секции рисков
     и цели плана (детализирует `/decompose-ticket`);
   - первая строка задачи — ссылка на план: `План: plans/P-NNN-<slug>.md`.
   Секции «Затронутые сервисы», «Изменения контрактов», «Подзадачи»
   НЕ заполняй — это работа `/decompose-ticket`.
4. В шапке плана заполни `tickets:` списком созданных файлов,
   поставь status: converted.

## Выход

Созданные тикеты + резюме: сколько, в каком порядке, какие зависимости.
Следующий шаг — `/decompose-ticket` по первому тикету.
