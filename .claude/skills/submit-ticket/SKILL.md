# Submit: реализация → PR-ы

Вход: путь к тикету в `tickets/in-progress/`.

## Предусловия (при нарушении — остановись и скажи почему)

1. В «Журнале» тикета зафиксированы `approve` от cross-review и зелёный
   integration-check. Не находишь записей — спроси у пользователя явное
   подтверждение, что стадии пройдены; без него не продолжай.
2. Worktrees ветки тикета существуют (`git -C workspace/<svc> worktree list`)
   для всех затронутых сервисов, в них нет незакоммиченных изменений.
3. `gh auth status` — ok. Нет — попроси пользователя выполнить
   `! gh auth login` и остановись.

`<tid>` ниже — идентификатор тикета (он же имя ветки), например
`T-001-transfer-fee-1pct`.

## Шаги

### 1. PR по каждому затронутому сервису

Для каждого сервиса с worktree `workspace/<svc>-<tid>`:

1. `git -C workspace/<svc>-<tid> push -u origin <tid>`
2. Собери тело PR из тикета (пиши во временный файл, не инлайном):
   - подзадача этого сервиса — дословно;
   - что изменилось в контракте сервиса (из секции «Изменения контрактов»);
   - критерий приёмки, относящийся к сервису;
   - строка «Тикет: `<tid>` в метарепозитории payment-processor-meta»;
   - итог cross-review по этому сервису (одной строкой).
3. `gh pr create --repo Mashoshin/<svc>-api --base main --head <tid>
   --title "<tid>: <короткое название тикета>" --body-file <tmp>`
4. Запомни URL созданного PR.
5. Убери worktree и локальную ветку (она уже на origin):
   `git -C workspace/<svc> worktree remove ../<svc>-<tid>`
   `git -C workspace/<svc> branch -D <tid>`

### 2. Ссылки в тикет, тикет — в review

1. Добавь в тикет секцию `## Pull Requests`: строка на сервис —
   `- <svc>: <URL>`.
2. Перенеси файл тикета из `tickets/in-progress/` в `tickets/review/`.

### 3. PR-«зонтик» в мете

1. В корне меты: `git checkout -b <tid>`.
2. Закоммить всё относящееся к тикету: `contracts/`, `plans/P-*`,
   `tickets/review/<tid>.md`, `sessions/`, прочие изменённые файлы меты.
3. `git push -u origin <tid>` и
   `gh pr create --repo Mashoshin/payment-processor-meta --base main
   --head <tid> --title "<tid>: <название>" --body-file <tmp>` —
   тело: сводка тикета (цель, затронутые сервисы) + список PR сервисов
   ссылками.
4. **Верни мету на main**: `git checkout main`. Рабочая копия меты не должна
   остаться на ветке тикета.

### 4. Итог пользователю

Таблица всех PR (сервис → URL, включая мету) и напоминание:
ревью и merge — руками на GitHub; когда все PR влиты — `/close-ticket`.

## Ограничения

- Ничего не мержить и не закрывать — только PR-ы.
- Код в worktrees не менять: нашёл незакоммиченное или красное состояние —
  это возврат на предыдущие стадии, не «быстро поправлю».
