# Метарепозиторий платёжной системы

Ты находишься в **метарепозитории** — координационном слое системы из трёх
микросервисов (payments, ledger, notifications). Кода сервисов здесь нет:
здесь карта системы, контракты, тикеты и процедуры работы.

## Порядок знакомства с системой

1. `map.md` — архитектура, связи, сквозные инварианты.
2. `registry/<service>.md` — манифест конкретного сервиса.
3. `contracts/<service>.openapi.yaml` — API сервиса. **Источник правды — здесь**,
   а не в коде сервиса. Если код расходится с контрактом — это баг кода.

## Правила (обязательны, без исключений)

1. **Contract-first.** Любое изменение поведения на границе сервисов начинается
   с правки контракта в `contracts/` в рамках тикета, и только потом — код.
   Правка `contracts/` без тикета в `tickets/in-progress/`, где эта правка
   заявлена, запрещена (и блокируется хуком).
2. **Plan-first, ticket-driven.** Работа над системой ведётся только через
   тикет, а тикеты пишутся агентом из утверждённого плана
   (`/plan-to-tickets`), не руками. Человек пишет только исходную идею,
   отвечает на возражения гриля и утверждает план.
   План (`plans/`) обязателен, если изменение затрагивает больше одного
   сервиса, меняет контракты или инварианты; мелочь внутри одного сервиса
   можно вести тикетом без плана.
3. **Границы сервисов.** Агент, реализующий подзадачу сервиса X, работает
   только в worktree сервиса X. Чужие сервисы — только через их API по контракту.
   Прямой доступ к чужому хранилищу (`var/`) запрещён всегда.
4. **Автор не проверяет себя.** Cross-review диффов делает отдельный агент,
   не участвовавший в реализации.
5. **Инварианты из `map.md`** (деньги в копейках, формат счетов, формат ошибок)
   не обсуждаются в рамках тикета — их изменение это отдельный тикет уровня системы.
6. Рабочие копии сервисов живут в `workspace/` (не под git метарепо).
   Разворачиваются через `scripts/bootstrap.sh`.

## Workflow (скиллы)

| Скилл | Что делает |
|---|---|
| `/draft-plan` | идея в свободной форме → структурированный план в `plans/` |
| `/grill-plan` | адвокат дьявола: атакует план (макс. 2 раунда), вердикт |
| `/plan-to-tickets` | утверждённый план → тикеты в `tickets/open/` |
| `/decompose-ticket` | тикет → затронутые сервисы, правки контрактов, подзадачи |
| `/implement-ticket` | подзадачи → параллельные агенты в worktrees сервисов |
| `/cross-review` | сверка диффов всех сервисов с контрактом и между собой |
| `/integration-check` | запуск всех сервисов + сквозной smoke-тест |

Полный конвейер:

```
идея → /draft-plan → /grill-plan (⟲ пока needs-work, ≤2 раундов)
     → approved (ставит человек) → /plan-to-tickets
     → /decompose-ticket → утверждение → /implement-ticket
     → /cross-review → /integration-check → merge → done
```

Статусы плана: `draft → grilled → approved → converted`. Approved ставит
только человек — это подпись под решением.

## Команды

```bash
scripts/bootstrap.sh      # клонировать/обновить сервисы в workspace/
scripts/run-all.sh        # поднять все сервисы (пиды в workspace/.pids)
scripts/stop-all.sh       # погасить все сервисы
scripts/smoke.sh          # сквозной smoke-тест (сервисы должны быть подняты)
```
