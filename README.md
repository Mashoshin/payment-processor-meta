# Метарепозиторий платёжной системы

Координационный слой для агентной разработки системы из нескольких
микросервисов. Кода сервисов здесь нет — здесь **знание о системе**
(карта, контракты, манифесты) и **процесс работы с ней** (планы, тикеты,
workflow-скиллы, хуки-ограничители).

Идея: агент, запущенный в этом репозитории (локально или в контейнере),
получает всё необходимое, чтобы вести изменение через несколько сервисов —
от идеи до merge — не разъезжаясь в контрактах и не нарушая границ.

## Система

```
  client
    |
    v
 [payments :8081] --(1) POST /entries--------> [ledger :8082]
    |
    +--------------(2) POST /notify----------> [notifications :8083]
```

| Сервис | Роль | Репозиторий |
|---|---|---|
| payments | оркестратор: приём платежа, проведение потока | [payments-api](https://github.com/Mashoshin/payments-api) |
| ledger | журнал проводок (двойная запись), источник правды о деньгах | [ledger-api](https://github.com/Mashoshin/ledger-api) |
| notifications | уведомления по счетам | [notifications-api](https://github.com/Mashoshin/notifications-api) |

Подробности: [`map.md`](map.md) — связи, поведение при сбоях, инварианты;
[`registry/`](registry/) — манифест каждого сервиса; [`contracts/`](contracts/) —
OpenAPI, **источник правды об API** (код обязан соответствовать контракту,
не наоборот).

## Быстрый старт

Требуется PHP 8.3+ и git. Фреймворков и composer-зависимостей нет.

```bash
scripts/bootstrap.sh   # клонирует сервисы в workspace/ по манифестам registry/
scripts/run-all.sh     # поднимает все сервисы; топология (URL соседей)
                       # собирается из манифестов и передаётся через окружение
scripts/smoke.sh       # сквозной smoke-тест: платёж → проводка → уведомление.
                       # Идемпотентен: уникальные счета на каждый прогон
scripts/stop-all.sh    # гасит сервисы
```

`workspace/` — рабочие копии сервисов, в git меты не входят (.gitignore).

## Процесс: от идеи до merge

Человек пишет идею в свободной форме, отвечает на возражения и утверждает.
Всё остальное — планы, тикеты, декомпозицию, код, ревью — пишут агенты.

```
идея → /draft-plan → /grill-plan (⟲ ≤2 раундов) → approved (человек)
     → /plan-to-tickets → /decompose-ticket → утверждение (человек)
     → /implement-ticket → /cross-review → /integration-check → merge
```

| Скилл (`.claude/skills/`) | Что делает |
|---|---|
| `/draft-plan` | идея → структурированный план в `plans/` (минимум два варианта решения) |
| `/grill-plan` | адвокат дьявола: атакует план по 6 линиям, максимум 2 раунда |
| `/plan-to-tickets` | утверждённый план → тикеты в `tickets/open/` |
| `/decompose-ticket` | тикет → затронутые сервисы, правки контрактов, подзадачи |
| `/implement-ticket` | параллельные субагенты по worktree на каждый затронутый сервис |
| `/cross-review` | независимые ревьюеры: сверка диффов с контрактами и между собой |
| `/integration-check` | запуск всех сервисов + smoke + критерий приёмки тикета |

## Правила и их enforcement

Правила описаны в [`CLAUDE.md`](CLAUDE.md); ключевые подкреплены механизмами,
а не просьбами:

- **Contract-first** — правка `contracts/` без тикета в `tickets/in-progress/`
  блокируется PreToolUse-хуком (`scripts/hooks/contract-guard.sh`);
- **автор не проверяет себя** — гриль и ревью выполняют отдельные субагенты;
- **границы сервисов** — агент сервиса X работает только в worktree X,
  чужие сервисы доступны только через их API по контракту.

## Структура

```
CLAUDE.md        правила и точка входа для агента
map.md           карта системы: связи, сбои, инварианты, осознанные дыры
registry/        манифесты сервисов (name, repo, port — источник топологии)
contracts/       OpenAPI-контракты — источник правды об API
plans/           планы: draft → grilled → approved → converted
tickets/         тикеты: open/ → in-progress/ → done/
.claude/skills/  workflow-скиллы (см. таблицу выше)
.claude/settings.json + scripts/hooks/  хуки-ограничители
scripts/         bootstrap / run-all / stop-all / smoke
workspace/       рабочие копии сервисов (не под git)
```

## Как добавить сервис

1. Положить манифест `registry/<name>.md` (name, repo, port, контракт).
2. Положить контракт `contracts/<name>.openapi.yaml`.
3. Дописать сервис в `map.md` (связи, поведение при сбоях).
4. `scripts/bootstrap.sh` — и bootstrap/run-all подхватят его без правки
   скриптов; все сервисы автоматически получат `<NAME>_URL` в окружении.
